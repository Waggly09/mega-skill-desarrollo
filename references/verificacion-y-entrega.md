# Verificación y entrega

## Prueba sobre una copia aislada

- Confirma qué proceso y base utiliza la prueba. Prepara datos sintéticos en una base y directorios temporales. Cuando cambies consultas, transacciones o migraciones, prueba en el motor del entorno objetivo además de la prueba rápida que corresponda. Para migraciones, ensaya tanto la instalación nueva como la actualización desde una versión anterior representativa.
- Usa los comandos de prueba y compilación del proyecto. Empieza por las reglas y contratos que cambian. Después prueba desde la interfaz con el perfil y dispositivo del puesto. Verifica que el resultado siga presente después de recargar. Si cambias permisos, reproduce la denegación con un perfil de otro ámbito.

## Promueve y documenta con evidencia

Para pasar del piloto a operación, identifica la versión, configuración necesaria, cambios de esquema, procedimiento de recuperación y responsables. Acuerda cómo importar o conciliar registros cuando se sustituya una herramienta existente. Verifica que la reversa sea compatible con los datos que puedan haberse guardado tras desplegar.

El piloto debe tener una planta o área definida, puestos participantes, casos de aceptación y un mecanismo para registrar incidencias. Recorre al menos un caso normal y una excepción con personal del proceso. Documenta qué se observó, qué problemas impiden ampliar el piloto y quién puede resolverlos.

Para reportar avances, vincula cada capacidad a una prueba, una pantalla o un registro del entorno evaluado. Usa datos sintéticos si compartes el material públicamente. Una cifra de ahorro, escalabilidad o cobertura requiere un método de medición o una hipótesis identificada.
